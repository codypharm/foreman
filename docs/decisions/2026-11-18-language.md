# Language: TypeScript everywhere

- **Date:** 18 November 2026
- **Status:** Accepted for William's areas. The chain readers part waits for Furqaan's agreement (see "Open")
- **Decided by:** William

## Context

Foreman has three parts in William's lane that share data: the valuation engine (with backtests and paper runs), the API and jobs, and the web app. Furqaan's chain readers produce the claim events and miner state the valuation engine consumes, and the data contract defines the shapes all of them pass around.

The only code today is `scripts/check_pod_mining.py`, a one-off chain check in Python with only the standard library.

## Options

| | Option | For | Against |
| --- | --- | --- | --- |
| **A** | **TypeScript everywhere** | The data contract is written once and imported by every part. viem reads the chain in the API and connects OKX Wallet in the web app. One language for two people in 18 days | Backtest analysis is clumsier than in Python |
| B | Python for the valuation engine and API, TypeScript for the web app | pandas makes backtests easier. Matches the existing chain check script | Shapes written twice, or generated from a JSON Schema. Two toolchains, two test setups |

## Decision

**A. TypeScript everywhere** for the valuation engine, option ranking, paper runs, the API and jobs, and the web app.

## Consequences

- The data contract's types are written once in TypeScript and imported by every part (location: see `2026-11-18-package-layout.md`).
- Chain reads use viem.
- **Token amounts are `bigint` in base units, never `number`.** BEM has 8 decimals; a JavaScript float would lose precision silently, which is exactly the kind of wrong nobody notices. Formatting to a decimal string happens only at display time. How ratios (miner weight ÷ network weight) and scenario multipliers are computed exactly is settled when the valuation engine is designed, with tests.
- `scripts/check_pod_mining.py` stays as it is: a one-off check, not part of the product.
- Test runner, Node version and other dependencies are chosen at scaffold time, each with what it costs.

## Open

- **Chain readers (Furqaan's area):** this decision works best if the BNB Chain and X Layer readers are also TypeScript with viem, so claim events reach the valuation engine in the contract's types with no translation layer. That is Furqaan's call. If he chooses another language, the readers hand over data in the data contract's shapes, and a new ADR records it.
