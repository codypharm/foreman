# Frontend: Vite, React, wagmi and viem

- **Date:** 18 November 2026
- **Status:** Accepted
- **Decided by:** William
- **Depends on:** `2026-11-18-language.md` (TypeScript everywhere)

## Context

The web app holds the miner page, the decision screen, the rules screens and the action log. It must:

- work with OKX Wallet first, and on mobile first;
- publish as a static mirror on DeWEB, so the build must be plain static files with no server rendering;
- support English and Chinese.

Every page is mocked with the `impeccable` skill and chosen by William before it is built (CLAUDE.md, "Frontend: mock first").

## Options

| | Option | For | Against |
| --- | --- | --- | --- |
| **A** | **Vite and React, wagmi and viem** | Builds to static files, so the DeWEB mirror needs no extra work. Largest choice of wallet components. Simplest | Routing and data fetching are put together by hand |
| B | Next.js with static export | Familiar, with conventions built in | Static export turns off server rendering and API routes, the features that make Next worth having |
| C | SvelteKit with its static adapter | Smaller bundles | Fewer ready-made wallet components |

## Decision

**A. Vite and React, with wagmi and viem for wallets and chain reads.**

## Consequences

- The app is a single-page app that talks to the Hono API. It holds no keys and no secrets; nothing in the client bundle is secret.
- OKX Wallet connects through wagmi's injected connector. Whether OKX's own Connect SDK is also needed for mobile deep links is checked when wallet connect is built.
- Check at build time how DeWEB serves paths: if it cannot send every path to `index.html`, the app uses hash routing.
- The routing, styling and translation libraries are chosen at scaffold time, each with what it costs.
