# Reading a published result back from X Layer

- **Date:** 23 November 2026
- **Status:** Accepted
- **Decided by:** William
- **Builds on:** `2026-11-21-results-contract.md` (the short verdict in storage, the full result in the `Published` log, tied by its hash), `2026-11-21-publish-job.md`, PRODUCT.md demo story step 5 ("show the transaction and read it back from the contract")

## Context

The result page's Published panel had a "Read it back from the contract" button that did nothing. The chosen result page mock showed the button but not what follows.

## Decisions

1. **The browser reads X Layer itself.** Foreman's API isn't in the path, so the visitor doesn't take Foreman's word for what the chain holds. On 23 Nov 2026 both public nodes, `testrpc.xlayer.tech` and `rpc.xlayer.tech`, allowed calls from a web page (`access-control-allow-origin: *`).

   The read is two calls at one block:
   - **The publish transaction's receipt.** Its `Published` log for this circuit carries the result's bytes.
   - **`resultOf(processor, id)`.** This is what the contract stores now.

   The page then checks the result:
   - It hashes the logged bytes itself and compares the hash with the stored one.
   - It decodes the bytes with the data contract's own `parseOriginality`.
   - It compares the decoded result with the result on the page.

   It reads only from a ForemanResults address listed in On-chain facts. A different address from the API is refused.

2. **What appears after the button: a checklist** (read-back A in `docs/mocks/2026-11-23-readback-and-loading.html`). Each check is one line in plain words, ticked or crossed:
   - "Found the publish": the transaction and its block.
   - "The contract stores this result": the hash.
   - "Same as this page": verdict, evidence, rule and BNB block.

   One line says the result was read straight from X Layer, at which block. Each way it can fail says why in plain words, never as a match:
   - X Layer doesn't know the transaction.
   - The transaction failed.
   - It holds no result for this circuit.
   - The logged result can't be read.
   - The contract now stores a later result.
   - The page shows a newer check that isn't published yet.

3. **While a result page loads: the page's shape** (loading A in the same mock). Grey shapes stand where the header, verdict and estimate will be, and the circuit number shows at once. Live listings and Your miners load the same way. The faster alternative, showing the stored verdict before the live reads finish, would split the API in two and change the data contract. It isn't built.

## Where the code lives

- **`@foreman/chain-xlayer/results`.** The contract's address, ABI and short verdict codes moved here from the publish job, so publishing and reading back share one source. `readPublishedResult` is here too, tested on a real testnet result replayed from a saved fixture (`fixtures/xlayer-published-result.json`). This entry point has no Node-only imports, so the web app can load it.
- **`ChainRead` is unchanged.** The data contract's `ChainRead` allows chains 56 and 196 only. The read-back is internal to the web app, so it carries its own block type, which allows the testnet.
