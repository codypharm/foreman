# API keys for markets and lenders: a bulk results call

- **Date:** 26 November 2026
- **Status:** Accepted
- **Decided by:** William, in a grilling of eight questions, each with a recommended answer and its alternatives
- **Extends:** `2026-11-26-revenue-and-reach.md` (the API column) and `2026-11-26-telegram-alerts-for-pro.md` (the build order). Neither is edited; where this record differs, it decides

## Context

`2026-11-26-revenue-and-reach.md` names an API as what markets, wallets and lenders would pay for: a check before a circuit is listed, bulk results, estimated values and payback, and a webhook when a copy is listed. None of it existed. Foreman's API had five GET routes (`/health`, `/check`, `/circuit/:processor/:tokenId`, `/listings`, `/wallet/:address/miners`), open to anyone with CORS `*` and no limit, and the web app calls them from the browser.

API keys are the second of three paid paths, planned for 29 Nov 2026 and second on the cut list if behind on 1 Dec.

## Decision

1. **A key unlocks one new call, a bulk results check.** Every existing route stays open and unchanged, so the web app is untouched. No webhook before the freeze.
2. **Each circuit's entry is its result and where it was published.** The result is the data contract's `Originality` as stored: verdict, evidence, can mine, coverage, rule version and block. "Where it was published" is the X Layer transaction from Foreman's record of what it published, so a market can check it on chain itself. No estimated value: that stays on the circuit page, and the API docs say so.
3. **A circuit with no stored result is built in the same call,** as the circuit page builds it (`scope: "pasted"`, never stored or published, so it has no published entry). This is the check before listing. A build that fails makes that circuit "Can't check" with its reason; the other circuits still answer. Never a silent "no earlier copy found". A miner whose result isn't stored yet is "Can't check: Foreman hasn't checked this miner yet", as on its result page: a miner is checked by the results job, never built as "pasted" (found while building, 26 Nov 2026: a pasted result can't carry a miner's design bonus).
4. **The request names circuits as `{chainId, processor, tokenId}`,** the data contract's circuit reference, which covers FabX circuits on X Layer (chain 196). Up to 100 a call. An unknown processor or circuit is "Can't check" with the reason.
5. **William issues keys by hand.** A command he runs (`pnpm --filter @foreman/api api-key create "<holder>"`) prints a new key once. Only its hash is stored in Postgres, with the holder's name and when it was made. Another command revokes a key. Partners ask William directly. No sign-up page and no billing before the freeze; the README says "ask for a key".
6. **Limits and records.**
   - Each key may make 60 calls a minute, counted in memory in the one API process. A call over the limit is HTTP 429 with `Retry-After`.
   - Every call adds to a count per key per day, in Postgres: calls and circuits. That is the basis for billing later, and a real number for the demo.
   - No monthly quota, no tiers, no prices.
7. **The call is `POST /v1/results`,** with a JSON body `{ "circuits": [...] }` and the key in `Authorization: Bearer fmn_…`.
   - Server to server only: `/v1` sends no CORS headers, so a key can't be used from a web page, where it would leak.
   - A missing, unknown or revoked key is HTTP 401.
   - A key is never logged or returned after it is made; logs name its id only.
8. **The README and the demo show it.**
   - The README gets an "API for markets and lenders" section: what it returns, one `curl` example with a trimmed response, the limits, and "ask for a key".
   - The demo video's business-model part shows one call against the hosted API for about 10 seconds, with the key hidden.
   - The API is described as "live, keys on request; billing next". No prices are named.

## Alternatives considered

- **Keys on the existing routes** (a limit per IP without a key, a higher one with): simpler, but the web app's own calls need a way around the limit, and a key buys nothing a market can't already get free.
- **A webhook when a copy is listed:** closest to the revenue record, but it needs signing, retries and a delivery store, about twice the work.
- **Values in each entry:** cheap only for listed circuits, whose weight is stored. Any other miner needs live chain reads per circuit.
- **A verdict only per circuit:** smallest, but breaks "every verdict carries its evidence".
- **"Can't check" for circuits that aren't stored:** fast, but leaves the main paid use, a circuit about to be listed, mostly unanswered.
- **Anything the Check box takes** (listing numbers, vouchers, miner keys): friendlier to people, but each item can be ambiguous or fail to resolve, and markets already know the processor and id.
- **A self-serve key page:** reaches people without William, but adds a page, abuse handling and an account model with three days to the cut line.
- **A rate limit only, or a monthly quota:** the first leaves nothing to bill on; the second implies tiers and prices, which aren't decided.
- **The key in a query string:** easy to try in a browser, but keys end up in logs, histories and referrers.

## What follows

- **Tests** (CLAUDE.md, "Published result" and "Bad input"):
  - A stored circuit returns its stored result and its published transaction.
  - An unstored circuit is built, with no published entry.
  - A failed build or an unknown circuit is "Can't check" with its reason, never "no earlier copy found".
  - A missing or revoked key is 401.
  - The 61st call in a minute is 429.
  - A call adds to the day's count.
- **A new migration** adds the keys table (key hash, holder, made, revoked) and the daily usage table.
- **The key commands run against Railway's Postgres.** William runs them with the database URL from Railway; an agent session never sees a real key.
- **On the cut list,** "API keys for markets and lenders" now means this call. If it is cut, the README and the video go back to "next".
- `2026-11-26-revenue-and-reach.md`'s "Foreman Pro and the API aren't built yet" no longer holds for the API once this ships. The README's business section says so when it ships.
